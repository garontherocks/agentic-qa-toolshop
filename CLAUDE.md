# agentic-qa-toolshop

Agentic QA suite for the **Restful-booker platform** (automationintesting.online), a public B&B booking app
built for practising testing, with a UI and a REST API under `/api`. (The repo name is historical: the suite
targeted Toolshop until Cloudflare started blocking CI runners there; that work is archived in `specs/archive/`.)
Tests are planned, generated, healed and reviewed by Claude Code agents over Playwright MCP,
with a human approving every change. Owner: Víctor Martín Aller.

## Commands

- `npm test` — every project · `npm run test:e2e` · `test:api` · `test:visual` · `test:a11y` · `test:smoke`
- `npm run typecheck` — must pass before any commit
- `npx playwright test <file> --project=e2e-chromium` — run one file while iterating
- Visual baselines are Linux-only: never run `test:visual:update` locally; CI regenerates them on request.

## Layout

- `tests/seed.spec.ts` — the agents' starting point. Human-written; do not let agents rewrite it.
- `tests/e2e` (Chromium, Firefox, WebKit) · `tests/api` · `tests/visual` · `tests/a11y`
- `src/pages` page objects · `src/api` typed API client · `src/support` fixtures, env, axe helper · `src/data` factories
- `specs/` — Markdown test plans written by the planner, one per area, plus `specs/coverage.md`
- `evidence/agent-runs/` — one log per agent session · `evidence/reviews/` — reviewer reports
- `.claude/agents` — planner, generator, healer (generated by `npx playwright init-agents --loop=claude`),
  plus `qa-manager`, `test-reviewer` and `failure-triager` (ours). Workflow: `docs/agentic-workflow.md`
- General engineering skills come from the `mattpocock-skills` plugin; where they overlap with this repo's
  skills (`suite-conventions`, `booker-domain`, `flaky-triage`, `evidence-log`), this repo's skills win.

## Rules for every agent and every change

1. **Plan → generate → run → heal → review.** No test merges without a plan in `specs/`, a green run and a
   reviewer report. The `qa-manager` agent drives this loop; humans approve between steps.
2. **Conventions live in the `suite-conventions` skill.** Read it before writing or changing a test.
3. **Domain facts live in the `booker-domain` skill.** Never invent URLs, ids, `data-testid` values, endpoints or accounts:
   verify them in the browser (Playwright MCP) or with an API call, then record them in that skill.
4. **The healer fixes tests, not the product.** If the app is wrong, mark the test `test.fixme()` with the reason
   and a link to the evidence; never weaken an assertion to make it pass.
5. **Shared demo.** The hosted app is used by many people: synthetic data only (`src/data/factories.ts`),
   no personal details, no load tests. Never change branding or other people's rooms, bookings or messages;
   clean up what you create when the API allows it (bookings can't be deleted there: create few).
6. **Evidence or it didn't happen.** Every agent session appends a log to `evidence/agent-runs/` using the
   `evidence-log` skill: what was asked, what the agent did, what a human changed, what was rejected.
7. **No secrets in the repo.** The demo admin account is public; anything else goes through env vars.
8. Never use `waitForTimeout`, `force: true`, `test.only` or retries to hide flakiness.
9. **Product findings stay out of the replay.** A test marked `fixme` for a product bug is listed in
   `specs/findings.md` (ID, evidence, test); the published run shows only tests that ran.

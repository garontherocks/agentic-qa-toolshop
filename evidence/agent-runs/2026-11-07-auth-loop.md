### Lockout of the demo account `customer@`
- During a `qa-manager` run, the shared `customer@practicesoftwaretesting.com` answered 423 (first seen at 04:15:51 UTC; it worked at about 04:00). The admin view showed `failed_login_attempts: 3`. A later run passed, so it was unlocked again; we did not unlock it.
- **Cause not determined.** In attempt 1 our agents made 7 failed logins against an account we could not identify. The lockout threshold is the 4th attempt. The suite code does not send a wrong password to any demo account; TC-03 is the only test that uses `customer@`, with the correct password.
- **How we avoid it from now on:** never a failed login against a demo account, neither in tests nor in live exploration (planner, generator, healer, triager or ad-hoc scripts). Wrong-password and lockout cases use only synthetic users that the test itself creates and deletes, or non-existent `@example.test` emails. Agent briefs state this explicitly.
